# 🔭 Further Reading & Where To Go Next

Once you've completed this repository, here's how to keep growing,
organized by direction.

## Official & Foundational
- **Python's official documentation** — https://docs.python.org/3/ — the
  ultimate reference once you know what you're looking for.
- **The Python Standard Library docs** — https://docs.python.org/3/library/
  — a huge amount of what you'll ever need is already built in.
- **PEP 8 (Style Guide)** — https://peps.python.org/pep-0008/ — the
  official style guide this repository follows.

## Practice & Reinforcement
- Solve beginner/intermediate problems on sites like Codewars, HackerRank,
  or Exercism to build speed and confidence.
- Re-read your own `19-projects` code a few weeks later — you'll spot ways
  to improve it, which is a great sign of growth.

## Web Development
- **Flask** — a lightweight framework, a natural next step for beginners.
- **Django** — a more full-featured framework for larger applications.

## Data Science / Analysis
This course's [`20-ai-ml-preparation`](../20-ai-ml-preparation/README.md)
gives you a first, deliberately shallow look at the libraries below. These
are where to go deeper:
- **NumPy** — numerical computing.
- **pandas** — data manipulation and analysis (spreadsheets, but in code).
- **Matplotlib / Seaborn** — data visualization.
- **Jupyter Notebooks** — an interactive way to explore data.

## Automation & Scripting
- Automating spreadsheets (`openpyxl`), sending emails, web scraping
  (`requests` + `BeautifulSoup`), or scheduling tasks.

## Testing
This course's [`16-testing-and-debugging`](../16-testing-and-debugging/README.md)
covers `unittest` and a `pytest` introduction already — these go further:
- Deeper `pytest`: fixtures, mocking, parametrization at scale.
- Continuous integration (running your tests automatically on every push).

## Version Control
This course's [`17-git-and-github`](../17-git-and-github/README.md) covers
the daily-use basics. Beyond that:
- Rebasing, resolving more complex merge conflicts.
- Pull-request-based team workflows, code review habits.
- GitHub Actions for automation (including running your `19-projects`
  tests automatically).

## General Advice
- Build things *you* care about. A project you're motivated to finish
  teaches you more than a tutorial you're not invested in.
- Read other people's code — browse small, well-written open-source
  projects on GitHub to see different styles and idioms.
- Don't chase every new library — depth in the fundamentals (which you now
  have) transfers to anything you pick up next.
